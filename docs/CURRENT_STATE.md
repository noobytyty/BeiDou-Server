### 2.1 装备词缀职业过滤

- 新装备生成时，武器按武器类别优先判断职业路线；非武器按 WZ 原始 `reqJob` 位标记过滤，`reqJob=0` 且明显偏法系的装备也不会放行力量/物攻词条。
- 战士武器（剑、斧、钝器、枪、矛）使用 STR/DEX；法杖和短杖使用 INT/LUK；弓弩使用 DEX/STR；短刀和拳套使用 LUK/DEX；指虎和手枪使用 STR/DEX。
- 武器属性类词缀只保留对应主属性、副属性、单属性/双属性组合及职业攻击组合，例如 `STR_WATK`、`DEX_WATK`、`INT_MATK`。
- `STR_MP`、`DEX_HP`、`INT_MDEF` 等混合词缀没有从数据库删除，仍兼容历史装备，并可用于非武器部位；只是不会再生成到新武器上。

### 2.2 词缀分解与魔法粉末

服务端分解逻辑已支持：分解带词缀的装备时，除原版制作结晶返还外，额外产出已有的 8 种魔法粉末：

| 粉末 | 道具 ID | 主要词缀类别 |
|---|---:|---|
| 褐色 | 4007000 | 基础属性、全属性及其他未分类属性 |
| 白色 | 4007001 | WATK、MATK、职业攻击组合 |
| 蓝色 | 4007002 | HP、MP、资源组合 |
| 绿色 | 4007003 | WDEF、MDEF、防御组合 |
| 黄色 | 4007004 | ACC、AVOID、命中防护组合 |
| 紫色 | 4007005 | SPEED、JUMP、移动组合 |
| 红色 | 4007006 | Boss、无视防御、掉落、经验、金币等特殊效果 |
| 黑色 | 4007007 | 火、冰、雷、圣元素伤害 |

- 每条词缀独立计算粉末数量：类别基础值（普通属性 1、攻击/资源 2、特殊/元素 3）+ `rarity / 2` + `ceil(T / 3)`。
- 同类粉末会在一次分解中合并；无词缀装备继续使用原版分解逻辑。
- 共享计算逻辑位于 `EquipmentAffixPowder.java`；Maker 分解入口位于 `MakerProcessor.java`，NPC 词缀分解入口位于 `SalvageEquipmentCommand.java`。两条入口都会按词缀追加粉末，NPC 分解确认框会显示预计金币和粉末产出；目前尚未完成真实客户端流程的完整实测。

### 2.3 词缀重铸粉末消耗

- 当前 `@reroll <装备栏位>` 命令已支持粉末消耗；重铸时只计算未锁定词缀，并按相同粉末分类和数量公式消耗材料。
- 锁定词缀不消耗粉末，并由现有 `preserveLocked=true` 逻辑保留。
- 重铸前会检查所有粉末库存；任一材料不足时，不扣金币、不扣粉末、不改变装备。
- 重铸仍保留原有金币费用；命令和 NPC 菜单都调用同一重铸命令，NPC 会在执行前显示预计金币/粉末需求并要求确认。
- 重铸消耗实现位于 `RerollAffixCommand.java`，粉末分类和数量复用 `EquipmentAffixPowder.java`。

## 6. 关键坑（快速避雷）

1. **xml-img-patcher 打客户端**：`export` 必须 `--context=2`（否则 hunk 从文件头开始 → 重复根节点损坏 img）
2. **单行 XML**（部分装备）：文本 diff 打不了，用 sync 或手工 MODIFY diff
3. **canvas 子节点 delay**：文本 diff 需完整 imgdir 上下文（`skill/xxx/effect/N/delay`），配 `--full-xml`
4. **NPC 渲染**：位置看服务端 spawn 封包；fh 必须对（全局段编号）
5. **伤害由客户端算**：改数值必须同步客户端 Skill.wz
6. **脚本每次点击重载**：改 .js 无需重启服务端；改 Java 必须停服→mvn package→重启
7. **推送需代理**：`git config --global http.proxy http://127.0.0.1:6382`
8. **gms-ui 的 yarn 改动**是环境噪音，不提交
9. **美容存档**：`beauty_slots` 表仍为 account_id 级，发型/脸型/肤色均使用独立槽位上限，`9977778` 保留存档、槽位购买和试衣间入口
10. **词条装备登录加载**：角色主加载路径使用 `InventoryService` 时必须恢复 `inventory_equipment_affix` 和 `rarity`，否则数据库中的显示总值会被当成本体值，装备升级会重复放大
