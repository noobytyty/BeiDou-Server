# 客户端资源同步执行清单（2026-09-04）

> 本文件供 AI 或维护人员在 **实际使用的 BeiDou 客户端仓库** 中执行。
> 不要使用服务端仓库内的原始客户端作为同步目标，也不要直接覆盖客户端原有资源。

## 1. 任务目标

完成今天服务端变更对应的客户端资源同步：

1. 回滚精通技能等级节点中的额外字段；
2. 同步现金商城武器的动作兼容节点；
3. 补齐现金武器名称和描述的 String 资源；
4. 检查商城商品是否引用了不存在的物品资源；
5. 不破坏客户端已有的 PNG、Canvas、Sound、UOL 和其他未涉及节点。

## 2. 必须提供的输入

执行前必须确认以下路径：

```text
SERVER_ROOT = BeiDou-Server 仓库根目录
CLIENT_ROOT = 实际使用的 BeiDou-Client 仓库根目录
PATCHER     = xml-img-patcher.exe 的实际路径
OUTPUT_ROOT = 客户端备份/输出目录
```

重要：

- `CLIENT_ROOT` 必须是玩家实际运行的客户端资源仓库；
- 不要使用 `SERVER_ROOT/beiDOU/BeiDou-Client` 作为判断依据；
- 先完整备份客户端 `Data/` 和 `EN/`；
- 所有写入优先输出到 `OUTPUT_ROOT`，确认无误后再替换正式目录。

## 3. 工具能力边界

工具支持：

```text
dump-xml       已有 IMG → XML
patch          对已有 IMG 应用 XML diff
batch          批量应用 diff
sync           服务端 XML 与客户端 IMG 节点级同步
verify         校验同步后的 IMG
```

工具不能完成：

- 从不含完整 PNG/Canvas/Sound 二进制内容的 XML 创建全新的 IMG；
- 为客户端不存在的 `017xxxx.img` 凭空生成完整外观；
- 自动获得实际运行版客户端中不存在的图片资源。

因此，缺失完整 IMG 时，必须从拥有该资源的运行版客户端复制，不能只依赖 XML。

## 6. 推荐执行顺序

### 步骤 A：备份

备份：

```text
CLIENT_ROOT/Data/
CLIENT_ROOT/EN/
```

保留原始目录，不要直接在唯一副本上操作。

### 步骤 B：同步精通技能

先执行预览：

```bash
"$PATCHER" sync \
  --server="$SERVER_ROOT/gms-server/wz/Skill.wz" \
  --client="$CLIENT_ROOT" \
  --out="$OUTPUT_ROOT" \
  --dry-run
```

检查结果：

- 只涉及 `Skill/110.img`、`1110.img`、`120.img`、`130.img`、`1310.img`、
  `1510.img`、`2110.img`、`310.img`、`320.img`、`420.img`、`510.img`；
- 不应出现大批无关 IMG；
- 不应新增重复的 `speed`、`pad`、`eva`、`pdd`、`mdd`；
- 如果工具只支持单个 IMG 输入，则逐文件执行 `patch`，不要扩大扫描范围。

确认预览无误后执行正式同步：

```bash
"$PATCHER" sync \
  --server="$SERVER_ROOT/gms-server/wz/Skill.wz" \
  --client="$CLIENT_ROOT" \
  --out="$OUTPUT_ROOT"
```

### 步骤 C：同步现金武器动作节点

预览服务端现金武器资源：

```bash
"$PATCHER" sync \
  --server="$SERVER_ROOT/gms-server/wz/Character.wz/Weapon" \
  --client="$CLIENT_ROOT" \
  --out="$OUTPUT_ROOT" \
  --dry-run
```

重点检查：

1. `017xxxx` 是否映射到 `Character/Weapon/017xxxx.img`；
2. 已存在的 IMG 是否显示 MODIFY，而不是重复 ADD；
3. 需要支持双手剑/双手斧的文件是否有 `40`、`41`；
4. 需要支持短杖/长杖、枪/矛、弓/弩、拳套/指虎/手枪的文件是否有对应根节点；
5. `01702345` 的 `30` UOL 是否指向有效动作，不得保留 `30 → 30` 自引用；
6. 不要把明确单手限制的 `1702204` 强行扩展。

### 步骤 D：补齐缺失完整 IMG

对服务端有 XML、客户端没有完整 IMG 的文件：

```text
从实际运行版客户端复制完整 017xxxx.img
再执行节点同步
```

禁止：

```text
直接把 XML 改名为 IMG
用不含图片二进制的 XML 空生成 IMG
把一个无关武器的 IMG 改名冒充目标武器
```

### 步骤 E：同步 String

分别处理：

```text
英文：String.wz/Eqp.img.xml → EN/String/Eqp.img
中文：wz-zh-CN/String.wz/Eqp.img.xml → Data/String/Eqp.img
```

执行时必须使用节点级合并：

- 保留客户端已有的 PNG、Canvas 和其他 `Eqp` 节点；
- 只更新或新增对应 `Eqp/Weapon/170xxxx`；
- 不要用不完整的中文 XML 覆盖完整客户端 String；
- 对缺少中文翻译的节点，保留英文基础资源作为明确回退，不要写入数据库键名。

### 步骤 F：校验

对每个实际修改的 IMG 执行：

```bash
"$PATCHER" verify <patched.img> <diff> <full-xml-or-dir>
```

校验要求：

- `miss=0`；
- 不存在重复数字根节点；
- 不存在 `30 → 30` 这种无效 UOL 自引用；
- IMG 可以被客户端资源工具正常打开；
- String 中目标 `170xxxx` 有 `name` 或明确的英文回退；
- Character/Weapon 中目标动作节点的 UOL 指向存在的源节点。

## 8. 失败处理

遇到异常时必须记录：

```text
SN
ItemId
客户端目标路径
服务端 XML 路径
缺失的 String 节点
缺失的动作根节点

```

不要直接扩大别名范围或覆盖整个 IMG。先确认是：

```text

客户端 IMG 缺失
客户端 String 缺失
动作根节点缺失
UOL 指向错误
```
