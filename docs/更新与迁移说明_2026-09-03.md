## 2. 调整内容

### 2.1 高级品质掉落权重

仅调整 Legendary、Ancient、Mythic，Epic 及以下品质不变：

| 来源 | Legendary | Ancient | Mythic |
| --- | ---: | ---: | ---: |
| 普通掉落 | 50 → 40 | 8 → 5 | 2 → 1 |
| Boss 掉落 | 1000 → 800 | 400 → 300 | 100 → 60 |
| 副本掉落 | 600 → 500 | 400 → 300 | 100 → 75 |
| 扭蛋掉落 | 600 → 500 | 150 → 120 | 50 → 35 |

这是相对温和的概率下调，不改变品质定义、词条数量或已有装备。按各来源权重总和估算，高级品质整体占比约为：

```text
普通掉落：0.60% → 0.46%
Boss 掉落：15.00% → 约 12.01%
副本掉落：约 10.68% → 约 8.68%
扭蛋掉落：8.00% → 约 6.65%
```

### 2.2 词条阶级抽取权重

T1-T2 保持常见，从 T3 开始逐级降低抽取权重，避免中高等级装备过于容易出现高属性：

| 词条阶级 | 原权重 | 新权重 |
| --- | ---: | ---: |
| T1-T2 | 100 | 100 |
| T3 | 100 | 95 |
| T4 | 100 | 90 |
| T5 | 100 | 80 |
| T6 | 100 | 70 |
| T7 | 100 | 60 |
| T8 | 100 | 50 |
| T9 | 100 | 40 |
| T10 | 100 | 30 |
| T11 | 100 | 20 |
| T12 | 100 | 12 |

词条数值范围仍使用现有配置，装备需求等级对应的阶级窗口也不变。
最终抽取仍会叠加距离装备等级均值的钟形权重；本次只是进一步降低高阶基础权重。
该调整只影响迁移执行后的新装备生成和重铸，不会重写已有装备。

### 2.3 品质对词条阶级的次级修正

在等级均值和阶级距离权重之后，装备品质会对 T5 以上阶级施加轻微乘区分化：

```text
品质 0（普通）：T12 约 0.92 倍
品质 1（精良）：T12 约 0.96 倍
品质 2（稀有）：T12 1.00 倍
品质 3（史诗）：T12 约 1.04 倍
品质 4（传奇）：T12 约 1.08 倍
品质 5（远古）：T12 约 1.12 倍
品质 6（神话）：T12 约 1.16 倍
```

品质不会改变装备需求等级、平均阶级、可抽取窗口或词条数量；它只让高品质装备在
同等级范围内略微更容易获得高阶词条，同时普通品质仍然是高阶词条的主要抑制来源。

## 3. 数据库迁移

新增：

- [V1.11.55__rebalance_high_rarity_and_affix_tier_weights.sql](/home/qtf8184/ms/BeiDou-Server/gms-server/src/main/resources/db/migration/V1.11.55__rebalance_high_rarity_and_affix_tier_weights.sql)

迁移内容：

1. 更新 `equipment_rarity_config` 中四类来源的高级品质权重；
2. 更新 `equipment_affix_range` 的 T3-T12 权重；
3. 不修改词条定义、名称、数值范围和已保存装备实例；
4. 不修改 `equipment_affix_pool` 或 `equipment_affix_level_pool` 的类型权重；
5. 不修改已经发布的迁移文件。

执行后可检查：

```sql
SELECT version, description, success
FROM flyway_schema_history
WHERE version = '1.11.55';

SELECT rarity, drop_weight, boss_drop_weight,
       dungeon_drop_weight, gachapon_drop_weight
FROM equipment_rarity_config
WHERE rarity BETWEEN 4 AND 6
ORDER BY rarity;

SELECT affix_tier, MIN(weight), MAX(weight), COUNT(*)
FROM equipment_affix_range
WHERE affix_tier BETWEEN 9 AND 12
  AND enabled = 1
GROUP BY affix_tier
ORDER BY affix_tier;
```

预期结果：

- `V1.11.55` 存在且 `success = 1`；
- Legendary/Ancient/Mythic 的来源权重与本文件一致；
- T9/T10/T11/T12 的范围权重分别为 90/75/60/45；
- T1-T2 权重未被本迁移改变；T3-T12 按本文件中的阶梯权重更新。

## 8. 现金商城武器槽位保护与兼容节点

- 服务端不会把 `170xxxx` 现金武器外观识别为真实 `SWORD1H`；这类物品是现金外观，
  `ItemInformationProvider.getWeaponType()` 返回 `NOT_A_WEAPON`。
- 现金武器只能进入现金武器槽 `-111`，普通单手剑仍使用真实武器槽 `-11`。
- 登录加载时发现历史现金装备位于普通负槽位，会转换到对应现金槽位，例如 `-11 → -111`。
- 已审计全部 1299 个 `170xxxx` 现金武器外观的根级 `imgdir`/`dir`/`uol`
  类型节点；对描述为“所有/任意武器”但遗漏 `48`（指虎）或 `49`（手枪）的
  37 个外观补充根级动作别名，避免它们被客户端误判为仅支持单手剑。
- 兼容别名复用同一物品已有画面，不新增美术资源；唯一仍仅保留 `30` 的
  `1702204` 描述明确为单手剑，属于有意限制。
- 额外修复 `1702345` 的 UOL 自引用：原先 `30 → 30` 没有实际动作目标，
  现已改为 `30 → 53`，其余类型别名可以正常解析到该道具的动作节点。
- 现金外观资源的兼容节点必须同步到客户端对应的 `Data/Character/Weapon/*.img`；
  这不是 ijl15 DLL 改动，客户端需要重新执行 IMG 节点同步后才能看到修复。
- 描述明确限制武器类型的现金武器不会被强行扩展，仍按原描述限制。

## 9. 虚拟背包入口道具栏目修复

- 卷轴背包 `2430011` 固定归入 USE 栏，矿石背包 `2430012` 固定归入 ETC 栏，
  不再仅按物品编号的百万位推断栏目。
- 角色登录加载时会归并历史重复或错放的入口道具，避免登录补发导致重复显示；
  修正后的物品也会使用正确栏目发送、移动和删除。
